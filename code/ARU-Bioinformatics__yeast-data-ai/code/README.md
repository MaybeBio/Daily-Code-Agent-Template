# Yeast, data and AI – which genes does yeast need to live?

**A self-contained, browser-based practical in AI-assisted data science for bioinformatics students.**

Students ask a real biological question – *which genes of baker's yeast are essential, and can a
computer learn to recognise them?* – and answer it the way much of bioinformatics is now done: a
table of data on 5,481 genes, a **Python notebook**, **machine learning**, a **protein language
model** (ESM-2), **AlphaFold** structures and a built-in **AI coding assistant**. The assistant writes
much of the code, and some of its answers contain deliberate mistakes (a mislabelled plot, the wrong
statistical test, a leaky model, a wrong reference) that students have to catch.

Nothing needs to be installed: Python runs inside the web page (Pyodide). The site is static
(HTML, CSS and JavaScript, no build step), so it can be hosted free on **GitHub Pages**. It was
written as a back-up practical for students who finish the variant-analysis practicals early, and
works as a stand-alone session (≈ 2½–3 hours) or as self-study.

## The practical

The instructions are on the left of the screen and a **workbench** on the right, with four tabs:
**Notebook** (real Python with pandas, scikit-learn, SciPy, matplotlib and seaborn), **AI assistant**,
**Data** (the gene table to browse without code, with a dictionary of the columns) and **3D viewer**
(AlphaFold models, coloured by confidence).

| # | Chapter | What students do | Time |
|---|---|---|---|
| 0 | Start here | The question, how the page works, start Python, meet the assistant | 5 min |
| 1 | The notebook | Load the table with pandas, count essential genes (1,041 of 5,481 = 19%), look up a gene, read the column dictionary, ask the assistant and insert its code | 15 min |
| 2 | Explore | Compare essential and non-essential genes; judge two AI-made plots – a box plot that hides the difference (needs a log scale) and a bar chart with the wrong labels | 25 min |
| 3 | Is it real? | The assistant uses a t-test on very skewed data; switch to Mann–Whitney U, effect sizes, multiple testing (Bonferroni) | 15 min |
| 4 | Teach a machine | A random forest with 95% accuracy and ROC AUC 0.98 – then the baseline (81%), feature importance and **data leakage**; an honest cross-validated model (AUC ≈ 0.81); thresholds, recall and precision; *extension:* a leaky text model | 30 min |
| 5 | Language model | ESM-2 embeddings: a map of the proteome, nearest neighbours (HXT1 → the hexose transporters), embeddings as features (AUC 0.76 alone, 0.83 with the other features) | 20 min |
| 6 | AlphaFold | Actin vs the FG-nucleoporin NUP1 in 3D; pLDDT and intrinsic disorder; are essential proteins more ordered? | 15 min |
| 7 | Learn from mistakes | The model's confident errors: “sticky” high-throughput interactors, wrong labels in the data (UTR5, TRE2), strain-dependent essentiality (HIP1 in a *his3* strain), genetic redundancy (paralogues), and a reference the assistant got wrong | 20 min |
| 8 | Using AI well | Review the assistant's mistakes, a checklist for AI-assisted analysis, AI and coursework, patient data, a short quiz, download answers and notebook | 15 min |
| 9 | Reference | Python cheat sheet, prompting tips, live-assistant notes, data sources | – |

Every step has a ▶ button that puts working code in the notebook or asks the assistant the right
question, so students without Python experience can follow; confident students can write their own
code. Steps tick themselves when done, answers are saved in the student's browser, and **My answers**
downloads them (with the student's name) as an HTML file. The notebook can be downloaded as a
Jupyter notebook (`.ipynb`) that opens in Jupyter, Google Colab or VS Code.

## The AI assistant

The assistant panel works in three ways.

**Guided mode (default – no account, no cost).** The practical's
questions have prepared answers, originally generated by an AI model and then checked and edited.
Six of them contain deliberate, realistic mistakes (see [Notes for staff](#notes-for-staff)). Answers
appear as if typed, with *Insert into notebook* / *Insert and run* buttons, and follow-up suggestions
appear under the chat (e.g. *“The boxes are squashed at the bottom – can you use a log scale?”*).
Students can also type their own questions: they are matched to the prepared answers, and anything
else gets an honest “I don't have a prepared answer” with the options below. **Ask AI → Explain this
code** on any notebook cell, and **Ask the AI to explain this error** under an error, give rule-based
explanations (e.g. *“'Essential' is not a column of df. Did you mean 'essential'?”*).

**Copy prompt.** Builds a complete prompt – a description of the data, the student's notebook code
and their question – and shows it (and copies it) so that students can read it and paste it into any AI
tool they are allowed to use (for example a university-licensed assistant). The code that comes back can
be pasted into a cell and checked.

**Live mode (optional).** In the assistant's settings (⚙) a user can connect a real model:
**Google Gemini** – offered first, because the Gemini API has a free tier; the default model is
`gemini-3.8-flash` – **Anthropic (Claude)** – the default model is `claude-sonnet-5-5` – or any
**OpenAI-compatible** service (base URL + model name). Typed questions go to that model: the
question, the notebook's code, a description of the columns and – when a student asks about a cell –
the start of that cell's output or error message are sent from the browser directly to the service
(the data files are not). The answer streams into the panel; *Stop* ends it. The ▶ buttons in the
instructions and the suggestions keep giving the practical's prepared answers, so the planted
mistakes and the self-ticking steps still work. Notes:

- **Never put an API key in `config.js` or anywhere in the repository** – anyone could copy it from a
  public site. Keys are typed into the settings dialog; by default they are kept only in memory, or
  in the browser tab's session storage if the user ticks *Remember* (cleared when the tab closes).
- For a class, the simplest options are: demonstrate live mode yourself on the projector; or let
  students make their own free Gemini key; or give students keys from a workspace with a
  **spending limit**; or leave it off and use *Copy prompt* with your institution's approved AI tool.
- **Gemini's free tier:** each student makes their own key with a Google account at
  [aistudio.google.com/apikey](https://aistudio.google.com/apikey). Google's terms for the free tier
  say that users must be 18 or over, that Google may use what is sent to improve its products, that
  human reviewers may read it, and that nothing sensitive, confidential or personal should be sent.
  The free tier also allows only a few requests per minute and per day, so each student should use
  their own key. Google's servers are sometimes busy for a model – most often the newest one – and
  answer “This model is currently experiencing high demand” (HTTP 503). The assistant then asks the
  next model in `geminiFallbackModels` (also when a model is over its free-tier limit or not found),
  and each answer says which model replied.
- Google's Gemini API accepts calls from web pages as it is. Anthropic's API accepts them when the
  request says so (the page sends the `anthropic-dangerous-direct-browser-access` header – the name
  refers to the risk of exposing a key in a public page, which is why keys are entered by users).
  Other services must allow cross-origin requests (CORS); a local server such as Ollama or LM Studio
  needs CORS enabled (e.g. `OLLAMA_ORIGINS=*`) and does not need a key.
- Check your module's and institution's policies on generative AI before asking students to use a
  live model.

## Put it on GitHub Pages

1. On GitHub, create a **new repository** (e.g. `yeast-data-ai`). It must be public unless your plan
   supports Pages for private repositories.
2. Upload the site so that `index.html` is at the **top level**, with `assets/` and `data/` beside it.
   - **In the browser:** *Add file → Upload files*, drag in the contents of the unzipped folder, then
     *Commit changes*. The whole site is about 6 MB.
   - **Or with git:**
     ```bash
     cd yeast-data-ai
     git init && git add . && git commit -m "Yeast, data and AI practical"
     git branch -M main
     git remote add origin https://github.com/<you>/yeast-data-ai.git
     git push -u origin main
     ```
3. *Settings → Pages → Build and deployment*: Source **Deploy from a branch**, branch **main**, folder
   **/ (root)**. Save.
4. After a minute the site is at `https://<you>.github.io/yeast-data-ai/`. Share that address (e.g. on
   Canvas) with the students who finish early.

The empty file `.nojekyll` stops GitHub from processing the site.

## Try it on your own computer

Opening `index.html` directly (`file://…`) does not work – browsers block the data files and the
Python worker. Serve the folder instead:

```bash
cd yeast-data-ai
python3 serve.py 8000        # then open http://localhost:8000
```

(`python3 -m http.server 8000` works too.)

## Notes for staff

**Model answers.** Every question except the final reflection has a model answer that students can
reveal with *Show answer* after trying (set `showModelAnswers: false` in `config.js` to hide the buttons; `?answers` at the end of the
address shows them again for staff). They are in the page source either way, so this practical is
designed for learning, not assessment.

**The assistant's deliberate mistakes** – the answer key for chapter 8 (the same information is in the
model answers students can reveal in the page):

| Chapter | Prepared answer | What is wrong | How students can catch it |
|---|---|---|---|
| 2 | box plot of protein abundance | linear axis: both boxes are squashed flat, yet the text claims a clear difference | look at the plot; the data span 6 orders of magnitude → log scale |
| 2 | % essential by location | bars sorted by height, labels left in alphabetical order – 5 of 8 labels wrong (the tallest bar, the nucleus, is labelled “Cytoplasm”); the text contradicts the plot | compare the bars with the printed numbers |
| 3 | “is the difference significant?” | t-test on extremely skewed data, “highly significant” with no effect size | remember the distribution; use Mann–Whitney U and an effect size |
| 4 | first machine-learning model | uses `conditional_mutant_phenotypes` (conditional alleles are made *because* a gene is essential – leakage), treats `chromosome` as a number, fills missing abundance with 0, calls 95% accuracy “excellent” without the 81% baseline | too good to be true; feature importance (0.61 for one feature); the column dictionary |
| 4 (extension) | text model on gene descriptions | AUC 0.92 because curators' descriptions contain “essential”, “viability”, “required” | look at the top words |
| 7 | reference for duplicate genes | Gu *et al.* (2003) is in *Nature* 421:63–66, not *Science* | check PubMed |

**Where students get stuck.** Python takes 10–30 s to start the first time (a status shows in the
notebook). After *Insert and run* the workbench shows the notebook; the follow-up suggestions are on
the **AI assistant** tab. Code from the assistant is added at the end of the notebook, because it
usually builds on the cells above. The cross-validated random forest takes a few seconds on a laptop (up to a
minute on slow machines). If a cell is taking too long, **Restart** resets Python (variables are lost;
*Run all* rebuilds them).

**Key numbers** (for marking discussions): 5,481 genes, 1,041 essential (19.0%); leaky model accuracy
0.945, AUC 0.978; honest logistic regression AUC 0.810 ± 0.015, random forest ≈ 0.81; threshold 0.5
finds 265 of 1,041 essential genes (precision 0.59), threshold 0.3 finds 583 (precision 0.47);
embeddings alone 0.76, features + embeddings 0.83; NUP1 mean pLDDT 44 with 83% of residues below 50.

## Settings: `config.js`

| Setting | Meaning |
|---|---|
| `showModelAnswers` | `true`: *Show answer* buttons under the questions; `false`: hidden (add `?answers` to the address to see them) |
| `pyodideBase` | where Python is loaded from – jsDelivr by default (see below to host it yourself) |
| `assistantDefaultMode` | `'guided'` (default) or `'live'`; live mode still needs each user to enter a key |
| `liveProvider` | the service offered first in live mode: `'gemini'` (default), `'anthropic'` or `'openai'` |
| `geminiModel`, `anthropicModel` | default models for live mode (users can change them in ⚙). Models are retired from time to time: if live mode reports that a model is not found, put a current one here ([Gemini models](https://ai.google.dev/gemini-api/docs/models)); students who have not typed a model of their own get the new one straight away |
| `geminiFallbackModels` | the Gemini models asked in turn when the chosen one is busy (HTTP 503), over its free-tier limit (429) or not found (404) – by default `gemini-3.6-flash`, then `gemini-3.5-flash-lite`; `[]` turns this off |
| `storePrefix` | name used for the answers and notebook saved in the browser; change it to give a new cohort a clean start |
| `afExample`, `pdbExample` | example text in the 3D viewer's load boxes |

**Hosting Python yourself** (e.g. if jsDelivr is blocked): download the Pyodide 0.29.5 release
(`pyodide-0.29.5.tar.bz2` from github.com/pyodide/pyodide/releases), unpack it into
`assets/vendor/pyodide/` and set `pyodideBase: 'assets/vendor/pyodide/'`. The full release is large;
the practical needs the core files plus the numpy, pandas, matplotlib, scipy, scikit-learn and micropip
packages and their dependencies (listed in `pyodide-lock.json`); micropip installs the bundled seaborn
wheel.

## Editing the content

- **Instructions and questions** are plain HTML in `index.html`, one `<section class="chapter">` per
  chapter. A question is a `<div class="q" data-q="unique-id">` with a `.q-text` and an optional
  `.q-model` (model answer); short answers can be marked automatically with `data-accept="regex"`;
  multiple choice uses `data-type="mcq"` with `<label data-correct data-why="…">`. A step that ticks
  itself has `data-task="id" data-auto="event key=value"` (e.g. `nb:run code~groupby ok=true` when a
  cell containing *groupby* runs without an error).
- **Buttons:** `data-ai="entry-id"` asks the assistant a prepared question; `data-nb-run="code"` runs
  code in a new cell; `data-af="P60010"` shows an AlphaFold model.
- **The assistant's prepared answers** are in `data/assistant.json`: each entry has an `id`, the
  `chapter`, the `prompt`, alternative phrasings (`alt`) and `keywords` (regular expressions) for
  matching typed questions, the `response` in Markdown (code in ```` ```python ```` blocks gets the
  insert buttons), and optionally `next` (follow-up suggestions), `followOnly` (only offered as a
  follow-up), `hidden` (never suggested, only matched to typed questions), `requires`/`excludes`
  (regular expressions a typed question must or must not contain) and `flawed` (contains a deliberate
  mistake – for your reference only). Entries with ids like `explain:load` answer *Explain this code*
  for the starter cell tagged `load`.
- The starter cells of the notebook and the column dictionary are in `assets/js/page-yeast.js`.

## Data

One row per nuclear, verified or uncharacterised *S. cerevisiae* (S288C) ORF with a recorded
result in the systematic deletion collection. `essential` = the deletion mutant is inviable. Features
come from SGD (sequences, phenotypes, GO locations), PaxDb v6.1 (protein abundance), BioGRID 5.0.261
(physical interaction partners), UniProt (transmembrane helices), DIAMOND searches (human homologue,
closest paralogue), the AlphaFold Database (mean pLDDT, disorder) and ESM-2 (embeddings).
`conditional_mutant_phenotypes` is a **deliberately leaky** column for the machine-learning chapter.
The full definitions, sources and the scripts that rebuild the files are in
[`data-build/README.md`](data-build/README.md). The data were downloaded on 30 September 2026.

## Privacy

Everything runs in the student's browser. The gene data are public. Answers, progress and notebook
cells are saved only in that browser (`localStorage`); nothing is sent to a server run by the
course. The page loads Python from jsDelivr and, in the 3D viewer, AlphaFold models from EBI (and
structures from the RCSB PDB if a PDB ID is typed). In live mode the assistant sends the student's
typed messages, the notebook code and, when they ask about a cell, the start of its output or error
message to the AI service the user chose – on Gemini's free tier, under Google's terms for unpaid
services (see *Live mode* above). HTML output in the notebook is sanitised (DOMPurify) before it is
shown. The practical reminds students never to paste personal or patient data into AI tools. If the
page is open in two tabs, it warns the student and keeps the answers saved from both.

## Browser support and network

Recent Chrome, Edge, Firefox and Safari on a laptop or desktop (the 3D viewer needs WebGL). Phones
and tablets work, but the screen is small for a notebook. The first visit downloads about 50 MB
(Python and its scientific packages); browsers cache it afterwards, so later visits start in a few
seconds. A class of students starting at once is fine for jsDelivr, but on a slow network ask
students to open the page a few minutes before they need it.
